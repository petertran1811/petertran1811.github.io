Generative video · AI-Core-Video · 2026

Character replacement in template videos

A user picks a template video (up to 60 s) and uploads one or two photos of people or pets. The service returns the same video with the characters replaced, shot by shot, with the right person in the right place on every frame.

Role
Designed and built the whole template mode: analysis, tracking, Wan Animate, QA, face swap, benchmarks and backend handover docs
Models
Wan 2.2 Animate 14B, MiniMax H3, SAM2, YOLO11, Qwen3-VL
Infrastructure
RabbitMQ worker, embedded ComfyUI, 48 GB L40S, 31 GB of checkpoints synced from S3

Pipeline

  1. Analysisffmpeg shot cuts; VLM: human or animal, which photo is who
  2. TrackingYOLO11 + BoT-SORT, ArcFace role match, SAM2 masks
  3. GenerationWan 2.2 Animate per person; H3 for animals
  4. QA + retryVLM, YOLO, leak check, ArcFace, time budget
  5. Post-processface swap + GFPGAN, skin tone, shot concat

Shots run one after another. A two-person shot runs two passes, the second on the output of the first.

What I did

  • Automatic template analysis. Shot cuts from scene-change scores (above 0.25, merged when closer than 0.4 s). A VLM picks the engine (people → Wan Animate, animals → H3) and assigns photos to roles by gender or species. Known templates reuse hand-checked shot plans.
  • The right person on every frame. Replaced keyframe heuristics (largest box, IoU) with YOLO11 + BoT-SORT ReID, matching tracks to photos by ArcFace similarity. Handles a first frame with nobody in it and tracks lost to smoke or sparks.
  • Two people in one frame. The other person is blacked out before pose detection so ViTPose locks onto the target; the SAM2 mask uses positive points on the target and negative points on the other person.
  • Keeping facial identity. Wan Animate keeps body, outfit and motion but the face drifts, so I added an ONNX face-swap post-process with colour and skin-tone matching. Fixed a "double eyes" bug on people with glasses: the occlusion mask treated lenses as occluders and blended them 50/50; a solid face-core mask now keeps only the frame rims.
  • QA with a time budget. Every pass is scored; retries only happen while budget remains (default 60 s of processing per video second).
  • Speed. fp8 tensor-core matmul (−10% sampling), SpargeAttn top-k 0.5 (−10%), 720p / 540p / 480p presets, and RAM-cache management to fit 55 GB RAM / 42 GB VRAM.

  • Measure on an idle GPU. The same work ran ~1.9× slower next to another job and nearly led to the wrong conclusion about presets.

  • A ReID tracker plus face-embedding role matching is far more robust than keyframe heuristics.
  • Automatic QA needs a time budget, or retries eat the SLA.

Production fixes

  • Corrupt input crashed the worker inside OpenCV / PyAV. I wrote a media guard: images are checked from their header before decoding; video and audio are probed and re-encoded with ffmpeg in a subprocess; bad files return 400.
  • Failed requests reported as successes. Exceptions carried no error code, so the queue sent a success with no file.

  • Stretched start images. The half-resolution latent floors to 32, so a 16-aligned canvas cropped and stretched the input; canvases now round to multiples of 64.

  • Optimize per component. LoRA merging, sampler changes and untiled decode only reach −30% together; no single change was enough.
  • Every default change needs an A/B on real images, and the cases not yet tested should be written down.
  • A GPU worker must treat every input as untrusted. Decoding in a subprocess is far cheaper than a dead pod.

Generative video · AI-Core-Motion · Oct 2026

Motion control with SCAIL-2 across multiple GPUs

Give it a photo of a person or an animal and a template video; it returns a ~10 s clip of that character performing the template's motion. I built the service on a 14B video model and made it scale across one to four GPUs.

Role
Built the service on SCAIL-2 (Wan 2.1 14B) + SAM3; optimized and ran it in production
Infrastructure
Embedded ComfyUI 0.18.1, all models resident on GPU, RabbitMQ worker, 1–4 L40S

Pipeline

  1. Subject detectionVLM: human or animal, species name for SAM3
  2. SAM3 trackingper-identity colour masks; ViT trunk on TensorRT
  3. SCAIL-2 samplingchained 81-frame chunks, Ulysses SP over N GPUs
  4. Post-processReal-ESRGAN to 720p, template audio copied
292 → 166 msper attention block with SpargeAttn top-k 0.5
~2×fp8 matmul vs fp16 on Ada, ~13 GB VRAM freed
43%of tracking time was the SAM3 ViT trunk, now on TensorRT fp16
4.5 sReal-ESRGAN compact 512p → 720p at 0.8 GB

What I did

  • Ulysses sequence parallelism for the 14B DiT. The ~50–77k tokens of each step are split across N GPUs; self-attention exchanges q/k/v with an NCCL all-to-all, pipelined over head groups so compute overlaps the ~15 GB per forward going over PCIe. VAE encode and decode are split too, and uneven splits work (40 heads on 3 GPUs = 14 / 13 / 13).
  • Two-pass chunk parallelism as the alternative: pass 1 samples every chunk at once, pass 2 re-samples them anchored on pass 1's tails, so 4 chunks on 4 GPUs take ~2 chunk times. Cross-fading was tried and dropped because it doubled the subject.
  • Real fp8 on Ada tensor cores. Every block's Linear swapped for an FP8 version. Measured per-layer error on real activations (2.2%), tried SmoothQuant, and kept one layer in fp16 because fp8 was no faster there.
  • SAM3 on TensorRT. The engine is keyed by GPU model, TensorRT version and a weight fingerprint, and falls back to PyTorch when they do not match.
  • Quality. Flat bright backgrounds (overcast sky, white backdrop) produce speckle that grows chunk by chunk: such images broke on 42/48 and 39/48 templates versus 4/48 for others. Added a background-risk rule and highlight compression of the start image.
  • Robustness. A GPU health check catches sticky CUDA errors, finishes the running request and exits so the pod restarts. This fixed a production incident where a broken worker kept taking jobs.

Lessons

  • A speed-up is worth keeping only if it speeds up the real configuration (4 GPUs). SmoothQuant was more accurate but not faster, so it went.
  • Multi-process GPU systems need clear exits: timeouts on collectives, and re-running a chunk on the main GPU when a worker dies.
  • Quality bugs that build up over time only show on large sets. You need per-template numbers, not a few demo videos.

Model compression · Solo · May – Oct 2026

Pruning & distilling Qwen-Image-Edit

Halving a 20B image-editing model on a single 96 GB GPU, then improving its realism and identity with a cleaner dataset, a reversed-direction LoRA and a retrained VAE decoder.

10.24Bparameters, down from 20.43B (−49.9%)
60 → 45DiT blocks kept
66.3 GBpeak VRAM while distilling (was > 96 GB)
75krealism samples after filtering

Pruning and distillation

The first attempt, cutting 60 blocks to 30, produced "melted" images. I traced it to three causes: blocks 1–28 were removed as one contiguous run, the block-selection metric was weak, and the training signal was too sparse (loss stuck at ~0.095). The redo had three stages:

  • Depth. Scored blocks three ways, including dropping one at a time and measuring the output; never drop more than 4 neighbours. 45 of 60 kept.
  • Width. Attention heads 24 → 12, FFN 12288 → 6144, chosen by activation magnitude; the model code still loads original checkpoints.
  • Distillation. A flow-matching distill loss learning from both data and the frozen 60-block teacher in fp8. Full fine-tuning plus the teacher ran out of memory; a rank-128 DoRA adapter brought peak use to 66.3 GB. I also wrote a DoRA merge script, because the standard LoRA merge ignores DoRA's magnitude vector.

Realism and identity

  • Data. 242,920 requests → MinHash-LSH template grouping (57,692 clusters), capped per cluster, photo vs stylized tags, 1,823 no-op edits and 12,109 face-changed pairs removed → 75,121 samples.
  • Realism LoRA "v7-flip". Reversed the training direction so the model learns to turn generated outputs back into real photos, escaping the teacher's quality ceiling.
  • VAE. v1 lost colour (learning rate 1e-4 and a trainable encoder, ~30% weight drift). v2 used 1e-5, a frozen encoder and a colour loss. A blur that only appeared in the full pipeline was fixed with a hybrid: original encoder, trained decoder.
  • Face-ID sets. 600 identities, 12k–36k pairs; v2 filtered with ArcFace to remove the 6–10% of pairs with the wrong identity.
  • Qwen-Image-2512. Merged LoRA + Lightning 4-step into FP8: ~20 GB instead of 40 GB in bf16. Wrote the cost estimate for full fine-tuning on 8×H20.

Model compression · Track A · Solo · Sep – Oct 2026

On-device image editing under 1 GB

Instruction-based photo editing that runs on an iPhone. Full fine-tuning of SD1.5 InstructPix2Pix (859.5M-parameter UNet), eight versions, each testing one hypothesis about the data.

What I found

  • The data was not editing. UltraEdit and MagicBrush change 7–8% of pixels; the in-house generated data changed 82%. Two-thirds of the set was really regeneration, so v1–v2 hallucinated details or could not change clothes.
  • v4 rewrote prompts with Qwen3-VL and got worse: the instruction's scope no longer matched the actual change.
  • v5 distilled from the production Qwen pipeline (Lightning 4-step, 45 s → 5 s per image). A VLM proposed 24k instructions, 12k pairs were generated in ~28 h, a 3-tier filter kept 11,687. v5 won every test case. Then v6 at 768px, v7 on a 482M UNet (BK-SDM), v8 with 37,841 teacher pairs.
  • Inference. Pasting the original face back cut face error 62–80%; blending unchanged areas at full resolution cut error 0.0164 → 0.0058; DPM-Solver++ at 10 steps takes 3.0 s vs 8.5 s for PNDM at 30 (2.8× faster).
  • CoreML. Exported with torch.export (jit.trace failed) and palettized to 4 / 6-bit for iOS 18. Not yet tested on a physical device.

Model size by quantization

Core model, 1.066B parameters. 6-bit palettization is the shipped choice.

A license-clean face swapper

The best face-swap models are licensed for non-commercial use only. In five days I built a one-shot swapper where every weight, line of code and dataset was license-checked at the source and logged with its SHA256 before use.

Scale

Pipeline

What I did

  • Replaced non-commercial parts. No insightface ArcFace / SCRFD, no VGGFace2 / CelebA / FFHQ. Trained my own ResNet18 478-point landmark regressor on MediaPipe pseudo-labels (NME 0.0232) to get a differentiable landmark loss.

  • Breaking the plateau. Three data-side fixes all stalled at ID-sim ~0.58. Rebalancing the losses pushed it to 0.62, and the landmark loss halved pose error from 8.3° to 4.2°.

Video Factory: book → audiobook & summary video

Give it a PDF or just a book title, free-text wishes and a voice. It returns a Vietnamese audiobook and an illustrated, subtitled summary video. A main agent coordinates 13 workers and may only deliver once three QA judges each score above 7/10.

Order flow

  1. IngestPDF → text
  2. SummarizeLLM
  3. IllustrateVLM → text-to-image
  4. NarrateVietnamese TTS
  5. Buildffmpeg
  6. QA × 3content, smoothness, voice
  7. Deliveronly after QA passes

On a QA fail the agent fixes images, re-records voice or tunes build settings, then repeats.

What I did

  • Vietnamese TTS. Three engines (VieNeu-TTS on CPU, F5-TTS-Vietnamese, OmniVoice with voice cloning), a pronunciation lexicon and spoken-math normalisation. Whisper large-v3 computes WER per chunk and re-records with a new seed on errors.
  • Judges. Content: a VLM checks images match the narration. Smoothness: no model, frame analysis for hard cuts, black frames and jerks. Voice: 10 − 30×WER minus a penalty per flagged chunk. They run in parallel across CPU and GPU.
  • Guardrails in code. The agent once called fix_images ~60 times in a row. Now only a QA-passed build can be delivered, deliver is the only allowed tool after a pass, three identical refused calls trigger give-up, and QA is capped at 8 rounds.
  • Dashboard. Animated agent graph, the main agent's thought stream, a Gantt chart of tasks, per-round QA chart, and ×20–×600 replay over SSE.

Agents that work through a multi-repo backlog unattended. Each order is a headless Claude Code session inside a service's repo: either an optimization (GPU rounds, VLM judging, pass at win rate ≥ 0.6) or a task with a machine-checkable acceptance command.

Size

What I did

  • Guardrails. A git shim blocks push, merge, hard reset and any branch outside the agent's prefix (tool allowlists can be bypassed; the shim sees the real arguments). $25 cost cap per order; protocol errors go to a human after 2 bounces; auto-resume after restart.

BuoyUp: five LLM agents that lend money

A working lending platform for e-commerce sellers with steady marketplace revenue but little bank credit history. Five AI agents take a seller from "paste my shop link" to money in the account. The design rests on one rule: agents choose, explain and check, but never create a money figure.

Project
Team entry for the "AI as a Financial Participant" theme. I wrote the technical report and the handover guide; the FISCO BCOS chain service is the team's own Go service.
Size
~21,600 lines of Python, ~10,800 of HTML / CSS / JS, ~120 REST endpoints, one FastAPI process with SQLite
LLM
Self-hosted model on vLLM through an OpenAI-compatible adapter, Gemini as a fallback provider; Agent 3 must run on a different model from Agent 2
0.59 → 0.82recall@5 on the held-out legal questions, lexical → hybrid

Loan pipeline

  1. 1 · Verifyshop ownership, tax revenue, credit, ID card OCR, risk flags
  2. 2 · Adviseturns the limit into options, chats with the seller
  3. 3 · Controlblind challenge, legal RAG, on-chain seal, gate
  4. Syndicatepartner banks decide in parallel within 30 s
  5. 4 · Payout & monitorone-time grant, collection, early warnings
  6. 5 · Post-auditreports and parameter proposals for a human

Every limit, rate, grade and schedule comes from a fixed credit algorithm (blocks B1–B12). Agents feed it verified facts and read its output.

Keeping the LLM in its lane

  • No free amounts. No tool in any agent accepts a loan amount. Agent 2 can only pick an option that already exists on the sheet.
  • Number filter. An outgoing message may contain only numbers present in the sheet or a tool result; internal thresholds are blocked.
  • Forbidden phrases per role. Promises of approval, payout or lower rates, threats and term changes. A hit discards the whole output and the template is used instead; output is never patched.
  • Prompt injection. Uploaded documents feed only fixed fields. Text aimed at the reviewer is recorded and escalates the case. Test cases for injection via chat and via data confirm the limit and proposal do not move.
  • An independent reviewer. Agent 3 judges blind, without Agent 2's rationale, and its phase-1 verdict is sealed on-chain before it may read and debate that rationale for at most two rounds. It can never go below the coded floor. In production the server refuses to start if both agents use the same model.
  • Graceful failure. Timeout, bad JSON or a schema mismatch returns nothing and the agent continues on its deterministic path. A circuit breaker stops calling an unreachable model server for 120 s, so every agent drops to templates at once instead of each request waiting through retries.

Legal RAG

Agent 3 checks each case against 794 articles from 14 Chinese laws and measures: the 2024 AML law, the e-commerce law, PIPL, internet-loan measures, the prohibited-goods list and more.

  • Lexical: BM25 over Chinese character bigrams, so no word segmenter is needed. Vietnamese and English queries are expanded with a glossary of Chinese legal terms.
  • Dense: multilingual-e5-large run locally, so a question in any of the three languages finds a Chinese article by meaning. Vectors are cached by model and corpus hash.
  • Fusion: reciprocal rank fusion, passages grouped per article. The 42-question dev set was used to write the glossary; the 22-question held-out set measures it.
  • Citations are checked, not trusted. Every rule's quote must match the article text verbatim and be in force on the date, or the rule is disabled at load time.

Retrieval only finds and shows law text. Decisions stay with the coded rules.

The first round found three real weaknesses: a cold-start trap that kept small sellers below the minimum loan, revenue inflated within tolerance, and counterfeit goods slipping through once a form field was removed. Each was fixed in code and parameters.

Lessons

  • When an LLM's action moves money, the model should choose among options code has already computed, never produce the figure itself.
  • Discard an unsafe output and fall back to a template. Repairing it invites the same failure in a new form.
  • A reviewer agent is only independent if it judges blind first and commits that verdict before it sees the other agent's argument.

AI Minichatbot: a self-hosted, OpenAI-compatible chat platform

The base service behind the company's in-app chat assistants. Apps call it with the standard OpenAI SDK, and it answers with in-house Qwen models served by vLLM, handling both text and images, with an agent that can search the web.

Models
Qwen3-8B-AWQ for text, Qwen2.5-VL-7B / Qwen3-VL-8B AWQ for images; can switch to OpenAI per request
Stack
FastAPI, LangGraph, PostgreSQL, vLLM, Docker images for the API, the LLM and the VLM

Request path

  1. ClientOpenAI SDK, bearer token, app and bundle IDs
  2. API/chat/completions or assistants → threads → runs
  3. AgentLangGraph ReAct with web search and page extraction
  4. ModelsvLLM: Qwen3 text, Qwen-VL images
  5. StatePostgres checkpointer, persona store

What it does

  • Drop-in OpenAI API. Chat Completions plus the Assistants model (assistants, threads, messages, runs, files) with the same request and response shapes and error codes, streamed over server-sent events. App teams switch by changing the base URL.
  • Multimodal input. Image URLs and base64 are accepted, HEIC photos from iPhones are converted to JPEG, and image requests are routed to the vision model.
  • Agent with tools. A LangGraph ReAct agent with Tavily web search and page extraction. When a search fails, the tool returns concrete suggestions (drop the time range, widen the topic) so the model can retry on its own.
  • Persistent conversations. Thread state is checkpointed in PostgreSQL through LangGraph's async and sync savers; assistant personas and their instructions live in Postgres with an in-memory cache.
  • Serving setup. vLLM with AWQ weights, prefix caching, chunked prefill, Hermes tool-call parsing, image pixel limits and a 32k context, so text and vision models can share GPUs.
  • Usage and cost tracking. Token counts per request (prompt, completion, reasoning), Prometheus metrics per assistant with daily rollover, an analytics event per call with time to first token, and LangSmith tracing.
